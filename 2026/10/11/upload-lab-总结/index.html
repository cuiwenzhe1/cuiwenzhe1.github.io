前言

依旧暑假期间通关的靶场，现在正好当作复习总结

Upload-Labs 是一个使用 PHP 语言编写的，专门用于学习文件上传漏洞的靶场。它包含了 21 种常见的文件上传漏洞场景，用来入门文件上传。
基于靶场的练习，掌握文件上传的基本绕过方法，校验原理，以及防范措施

本质

一个标准的文件上传功能流程是：用户选择文件 -> 浏览器将文件发送至服务器 -> 服务器接收并处理文件 -> 将文件存储在某个可访问的目录。漏洞产生的根本原因在于，服务器对用户上传的文件过于信任，缺乏足够、有效的校验，导致攻击者能够上传被服务器解释执行的可执行脚本（如PHP、JSP、ASP文件）。

  • 注意一句话木马的隔离，使用白名单，或者提前退出windows defender和杀软

MIME补充

MIME类型（Multipurpose Internet Mail Extensions，多用途互联网邮件扩展）是一种标准，用来标识文件的本质和格式。在HTTP协议中，它通过 Content-Type 这个字段来传递。
例如，当你上传一张图片时，浏览器发送的HTTP请求头中会包含类似这样的信息：

  • Content-Type: image/jpeg（表示JPEG图片）
  • Content-Type: image/png（表示PNG图片）

常见的MIME类型还有：

  • text/html：HTML文档
  • text/plain：纯文本文件
  • application/x-httpd-php：PHP脚本

Pass-11 %00截断

查看源码发现 ==启用白名单==

条件：主要影响 PHP 版本低于 5.3.4

原理：

PHP版本<5.3.4 时存在的漏洞，白名单校验时 %00（NUL 字符）后面的内容会被字符串处理函数截断，只看前面的 .php；保存时 %00 后的内容丢弃。本机 PHP 5.3.29 / 7.3.4 均已修复（PHP ≥ 5.3.4），做不出效果，仅当教学。

Pass-12、13 %00截断（POST 版）

同第 11 关，只是 save_path 变成了 POST 参数。POST 的 %00 需要在 Burp 里手动改为空字节，同样在 PHP ≥ 5.3.4 失效。

17 二次渲染绕过

最严格的图片上传验证，对上传的图片进行二次渲染，会破坏嵌入在图片中的恶意代码
GIF绕过方法：上传一张正常GIF图片，并下载渲染后的图片，使用010editor对比两张图片，找到渲染不改变的部分，把php代码转换为16进制，插入，再上传

总结：如果网站必须允许用户上传图片，那么将上传目录设置为不可执行，或者将图片存储到单独的静态文件服务器/对象存储，是更安全的做法

18 条件竞争

关卡提示：将上传文件先保存，再检查，不合格则删除，即存在一个时间窗口
利用bp的intruder

看运气，主要知道这种方法，熟悉bp用法

绕过方法：1.写一个不断生成木马的PHP脚本
2.使用bp的intruder模块，持续，重复的上传脚本
3.并同时快速访问 。。。。/upload/compete_shell.php
服务器端的流程：
请求A上传了 compete.php -> 文件被保存。

在它被删除前的一瞬间，请求B访问了 compete.php -> 该文件被执行，在我们的指定目录（如 upload/）下生成了一个新的、不会被删除的 Webshell compete_shell.php。
总结：安全检查顺序的重要性，先检查后保存

19 Apache 解析漏洞

在 Apache 1.x、2.x 中，存在一个解析漏洞：当遇到不认识的后缀时，会从后往前解析，直到遇到认识的后缀。
传shell.php.xxx 即可

总结

面对一个真实的上传点，检查清单应该是这样的：

信息收集：前端有无JS校验？Burp抓包看请求结构。尝试上传各种异常文件（超大文件、畸形文件名、不同后缀），观察错误信息。错误信息有时会泄露路径、服务器技术（Apache/Nginx/IIS）、后端语言（PHP/Java/.NET）等。
